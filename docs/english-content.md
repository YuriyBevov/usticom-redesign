# Контент и английская версия

Разработка выполняется локально в `dev`. Слияние в `main` запускает штатное обновление через GitHub Actions. В рамках этой задачи публикация на боевой сервер не выполняется.

## Где редактировать

В админке откройте **Контент → Контент сайта(EN)**:

- **Услуги (EN)** — английские карточки услуг, их тексты, кнопки и состав блоков.
- **Прайс-лист (EN)** — английские тарифы. Раздел тарифов выбирается в свойстве услуги «Price section».
- **Вопросы и ответы (EN)** — английские вопросы. Связи задаются в свойстве услуги «FAQ».
- **Тизеры (EN)** — четыре карточки первого экрана. Раздел выбирается в свойстве услуги «Карточки первого экрана».
- **Страницы и SEO (EN)** — заголовки и метаданные страниц `/en/`, `/en/services/`, `/en/contacts/` (коды `home`, `services`, `contacts`).

Новая английская услуга взята из второго документа. Она связана с русской услугой по аутсорсингу кадрового делопроизводства через свойство **Russian version**. Новая русская карточка аудита из первого документа находится в прежнем русском инфоблоке «Услуги», раздел кадровых услуг; её адрес — `/employ/audit-kadrovykh-dokumentov/`. Существующая карточка аудита сохранена.

Остальные услуги, новости и кейсы пока остаются на русском сайте. Для добавления английской услуги создавайте новый элемент в «Услуги (EN)», заполняйте его английским текстом и указывайте русскую карточку в **Russian version**. Меню и список услуг берут активные карточки из английского инфоблока.

## Title, Description и H1

Откройте нужную английскую услугу или элемент в «Страницы и SEO (EN)», затем вкладку **SEO**:

1. **Шаблон META TITLE** — заголовок вкладки браузера и поисковой выдачи.
2. **Шаблон META DESCRIPTION** — описание страницы для поисковиков.
3. **Заголовок элемента** — H1 на странице; при отсутствии значения используется название элемента.

В английской карточке эти поля заполняются английским текстом независимо от русской карточки. После сохранения Битрикс обновляет SEO-кеш. Для услуги из второго документа первоначальные Title и Description взяты из документа дословно. Поисковая система может сформировать собственный заголовок или сниппет.

## Общий интерфейс

Переводы общих подписей находятся в `local/php_interface/lang/en/interface.php`, сообщений браузера — рядом с кодом соответствующих форм и меню. Адрес и часы работы редактируются в `/en/include/`, меню — в файлах `.menu.php` английского раздела. Эти изменяемые файлы создаются из `deploy/defaults/en/` только при отсутствии и сохраняются при обновлениях. Телефон и почта используют общие включаемые области русского сайта.

Английская форма доступна в **Сервисы → Веб-формы**, символьный идентификатор `USTICOM_EN_REQUEST`. Подписи, описание, обязательность полей и уведомления редактируются там. Результаты сохраняются отдельно от русских форм. Почтовый шаблон привязан к форме; по умолчанию он использует стандартный email сайта Битрикс (`#DEFAULT_EMAIL_FROM#`). Получателя можно изменить в связанном почтовом шаблоне. Согласие записывается штатным механизмом Битрикса; ссылка на существующий русский юридический документ явно обозначена как русская.

## Как контент попадает из репозитория

Структура и первоначальные данные описаны в `local/migrations/`, исходный контент — в `local/migrations/content/`. Обновление запускает `local/tools/migrate.php --apply` **после резервной копии**, без импорта дампа БД.

Выполненные миграции записываются в базе. Повторный запуск пропускает их; импорт услуг дополнительно проверяет постоянный XML_ID и не обновляет существующие карточки. Изменения контент-менеджеров сохраняются. Для последующих изменений структуры создавайте новую миграцию; уже выпущенные миграции и их исходные данные не редактируйте.

Локальный запуск на этом MAMP:

```sh
npm run setup:content
/Applications/MAMP/bin/php/php8.2.20/bin/php -d short_open_tag=1 local/tools/migrate.php
/Applications/MAMP/bin/php/php8.2.20/bin/php -d short_open_tag=1 local/tools/migrate.php --apply
```

Вызов без `--apply` показывает план, вызов с `--apply` применяет изменения к локальной базе. Перед ним нужна резервная копия локальной базы. Настройки MAMP, дампы и загрузки не включаются в Git. На локальном стенде отключены отправка писем и запуск импортированных агентов; это локальные настройки, в релиз они не входят.

При ошибке обновления откатывается код. Рабочая база автоматически старым дампом не заменяется: новые записи и правки редакторов сохраняются. Резервные копии нужны для восстановления после отдельной диагностики.

Проверка заполнения и сохранности правок редактора на локальном MAMP:

```sh
/Applications/MAMP/bin/php/php8.2.20/bin/php -d short_open_tag=1 tests/integration/local-content.php --local-mamp
```
